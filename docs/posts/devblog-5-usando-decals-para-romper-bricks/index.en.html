In the end I decided to do the animation for when you start breaking a block. If I'm not mistaken, the technique of overlaying textures on top of others is called a decal.
An example would be bullet impacts in a level.

They adapt to the shape of the surface and, using parallax, they can even give a perforation effect and everything.

Unfortunately I have no clue at all about graphics stuff (decals are usually applied using Shaders and depend on the render pipeline you've chosen. I don't even know the differences between pipelines).

So I'll do something much simpler, without details like depth or adapting to the shape.
It'll be a texture that I'll place wherever the player is mining.

We start by looking for a breaking sprite:

We save it as a texture, assign the texture to a material and tweak the background transparency and the offset on it so only part of the texture is visible.

Now comes the nasty part, the code.
My idea is to create a class that handles its positioning and movement. At any given time we'll have just 1 animation, which we'll keep moving to whichever brick it belongs to.

The class will need to have the texture "frames"/offsets where each image is shown. We'll only put the animation in the scene if it actually gets used, so there are no extra objects.

Every so often while you're mining I'm already playing a sound effect, so we'll use that spot to advance the animation:

To figure out where to put it, we'll use the raycasting done earlier to know which block you want to mine. From it we can get the hit point and the angle. We can't use the hit point directly, because it's exactly where the face of the brick's model is. That leads to a problem known as "z fighting":

It's not very noticeable, but it's that flickering, the fight between showing the block's texture or the breaking one.
As a fix we can use the model's position: depending on where it is, we'll move the animation a tiiiiny bit forward/backward:

Much better:
With this, there's just one detail left, the size of the animation:

I can't think of any fix. If we always showed the animation in the center of the face, it'd just be a matter of using its height, but the hit point can be anywhere on the brick, so it'll always end up sticking out unless a decal is used

I'll have to get serious about graphics and start understanding what it's all about, time to do some research:

After this it's clear there are 2 paths to choose from when it comes to pipelines:
- URP: Meant for mobile and 2d, with new tools and lights for 2d.
- HDRP: Meant for PC/consoles, with RTX support, new light types, fabric shader, a built-in decal system, etc..
- BuiltIn: The system the project currently uses.


And, at least for me, it's even clearer which one to pick -> HDRP.
The game isn't 2d and the focus is for it to run on my gaming laptop, not on a phone. I won't be the one using all of HDRP's new features, but decals are something I want.

I've migrated the project to HDRP. Some things broke along the way, like the preview of the block you're about to place, but I think everything is fixed now.

Now we can get back to the original topic, the decal.
HDRP has a component called Decal Projector, and thanks to it we can put our texture over the block without it sticking out weirdly.
The class I had written to spawn the texture, position it and animate it works almost perfectly with the Decal Projector. Thank goodness, we didn't waste our time.

It doesn't stick out anymore!
